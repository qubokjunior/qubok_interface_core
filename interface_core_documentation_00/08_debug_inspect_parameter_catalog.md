# 08 — Debug inspect parameter catalog

Status: draft 00
Scope: parameters visible/readable in debug inspect, inspector, hover inspect, spreadsheet, hierarchy, theme/preset/source diagnostics

## 1. Purpose

This document defines the catalog of parameters that `qubok_interface_core` may display, read, filter, colorize, compare or edit when inspecting an element in debug/inspect mode.

The goal is to make the following views consistent:

```text
Inspector
Debug Hover Card
Pinned Debug Inspector
Hierarchy / Layers
Logic Spreadsheet
Library Usage View
Theme / Preset Variation View
Validation Panel
```

Core rule:

```text
inspect displays data from Project model and derived runtime diagnostics
inspect does not create a separate source of truth
```

## 2. Parameter metadata model

Every inspectable parameter should be described with metadata.

Recommended fields:

```text
id
label
group
kind
value_type
tags
maturity
weight
read_access
write_access
source_mode
source_chain
owner_scope
display_mode
debug_color_token
validation_policy
when_visible
short_description
```

Meaning:

| Field | Meaning |
|---|---|
| `id` | stable path-like identifier |
| `label` | compact UI label |
| `group` | identity, transform, style, region, layout, hierarchy, etc. |
| `kind` | stored, computed, inherited, runtime, debug, reference |
| `value_type` | integer, float, vector2, vector3, color, enum, boolean, array, object, reference |
| `tags` | search/filter metadata |
| `maturity` | spec, headless, debug, MVP, polished, advanced |
| `weight` | ordering in inspector/debug/spreadsheet |
| `read_access` | visible, debug_only, advanced_only, hidden |
| `write_access` | editable, read_only, locked, computed, inherited, dictated |
| `source_mode` | default, local, inherited, dictated, theme, preset, graph_output, calculated |
| `source_chain` | where value came from |
| `owner_scope` | project, object, group, component, panel, workspace, runtime |
| `display_mode` | row, chip, swatch, badge, tree, table, overlay, graph |
| `debug_color_token` | semantic color used in debug |
| `validation_policy` | allowed range/type/rule |
| `when_visible` | condition for showing parameter |
| `short_description` | one-line explanation |

## 3. Source and override model

Each parameter may come from one source or be resolved through a chain.

Source modes:

| Source | Meaning | Write behavior |
|---|---|---|
| `default` | type/system default | editable only through preferences/defaults |
| `local` | stored directly on object | editable |
| `internal` | local/internal value of element/component | editable if not locked |
| `theme_token` | value from theme/preferences | edit through theme or override locally |
| `preset` | value from style/component preset | edit by overriding or changing preset |
| `inherited` | received from parent/group/panel/component | read-only locally unless override created |
| `dictated` | forced by parent/rule/state | read-only until rule disabled/changed |
| `component_parameter` | exposed parameter from component instance | editable at component interface level |
| `state_override` | active state variant, for example hover/active | usually runtime/debug; may be edited in state editor |
| `linked_reference` | reads another parameter/object | edit link or source object |
| `graph_output` | generated by event/action/state graph | runtime-controlled; edit graph/assignment |
| `calculated` | computed from geometry/layout/runtime | read-only |
| `runtime_debug` | current live diagnostic state | read-only |

Priority proposal:

```text
locked explicit override
> local override
> dictated rule
> active state override
> graph runtime output if allowed
> component exposed value
> linked reference
> preset
> theme token
> parent inherited
> default
> calculated fallback
```

## 4. Change-color semantics

Debug/inspect should color parameter rows by meaning, not decoration.

| Color token | Meaning |
|---|---|
| `param.default` | default unchanged value |
| `param.local` | locally stored value |
| `param.inherited` | inherited value |
| `param.dictated` | forced/narzucone by rule/panel/state |
| `param.changed` | changed from default/preset |
| `param.added` | added/new field or object |
| `param.removed` | removed/deleted/disabled reference |
| `param.overridden` | override exists |
| `param.graph_output` | driven by graph/action |
| `param.warning` | valid but suspicious/conflicting |
| `param.error` | invalid/broken/blocking |
| `param.locked` | locked/read-only |
| `param.mixed` | multi-selection has different values |

The Preferences panel should allow customization of these semantic colors.

Weight ranges:

| Weight | Group |
|---:|---|
| 0–99 | identity/core identifiers |
| 100–199 | hierarchy/ownership |
| 200–299 | transform/geometry/bbox |
| 300–399 | style/text/visual |
| 400–499 | region/layout/panel/component |

## 22. Multi-selection behavior

When multiple objects are selected:

| Case | Display |
|---|---|
| all values same | show value normally |
| values differ | show `mixed` |
| field missing in some objects | show `partial` |
| field read-only for some | show warning/partial lock |
| action applies to subset | show affected count |
| source differs | show mixed source chips |

Example:

```text
color_main: mixed [3 values]
source: local x2, inherited x1, dictated x1
affected if edited: 4/4
```

## 23. Theme variation versus structural variant

A preset/theme variation changes parameters of the same object structure.

Examples of theme/preset variation:

```text
button color changes
slider stroke width changes
panel radius changes
text color switches to warning token
hover state uses different fill
```

A new group/panel/component variant changes structure.

Examples of structural variant:

```text
button gains icon child
slider gains second handle
panel gets new footer group
dropdown gets search input
component child count or role map changes
```

Debug inspect should show:

```text
structure_signature
theme_variation
changed_parameters
is_structure_variant
```

## 24. Acceptance rule

The debug/inspect parameter catalog is valid when:

```text
all fields have id, group, type, tags, weight, read/write access and description
source mode is visible or debuggable
original/local/resolved values can be compared
changed/default/removed/overridden states can be colorized
parameters can be searched and filtered like spreadsheet data
events/actions/regions/panels/theme variations are visible in one inspect model
workspace window state is separated from canvas object panel state
```
